# 配方 = 一次性启动器，调试即编程（已废弃，见 ADR-0005）

> Status: superseded by ADR-0005

组装器（pi-coding-agent）接收人的需求，输出结构化配方；接线引擎按模板把配方落地成第一个可运行的 demo 起点；生成后配方即弃，demo 成为普通代码，由 pi-coding-agent 直接改码迭代。不维护配方真相源，不做配方同步回写。

未来读者会问"为什么不直接让 AI 从零写 demo，或让配方保持同步"——答案：模板保证起始版本正确可复现（防 AI 编造接口）；配方不留版本同步负担；调试即编程，代码是唯一真相源。

ADR-0005 推翻了"配方 + 接线引擎"的结构：配方只对出生那一刻正确，demo 一旦被改就追不上实例；接线引擎模板编码的正是最易被真实业务重写的 agent loop。保留的遗产是"调试即编程、代码是唯一真相源"——它正是 ADR-0005 的基石。

## 调研修订（research/02）

- 定位是"脚手架生成范式 + LLM 组装器"的刻意组合，非创新；主动避开"配置当长期真相源"的公认坑（配置与代码双份漂移，不可维护）。
- 补充：**导出时物化一份"组装记录"（build-note）**——配方本身即弃，但"当初怎么选的"要物化下来随导出项目保留，否则导出后想回看生成时的选择无从谈起（Dify build_note 教训）。
